## Miljöproblem

Docker CLI och Docker Compose är installerade:

- Docker `29.5.3`.
- Docker Compose `v5.1.4`.

Docker-motorn körs däremot inte. `docker compose up -d db` misslyckades med
att ansluta till Docker Desktop Linux Engine. Den lokala Windows-tjänsten
`com.docker.service` var stoppad och kunde inte startas från agentens miljö.

Konsekvensen är att integrationstesterna inte kan klassificeras som gröna eller
röda kodfel ännu. De är miljöblockerade tills PostgreSQL kan startas.

## Vad som fungerade

- Node-beroenden kunde installeras.
- ESLint passerade.
- TypeScript typecheck passerade.
- Python-beroenden från `requirements.txt` kunde installeras.
- Pytest kunde starta.
- Extern Git-remote är borttagen.

## Vad som misslyckades

- PostgreSQL kunde inte startas från denna miljö.
- Jest-testsviten kunde därför inte köra sina databasresetar.
- Prettier-kontrollen är inte grön.
- Legacy-delen har inga tester ännu.
- Docker-tjänsten kunde inte startas av agenten.

## Beslut

1. Baslinjen sparas som miljöblockerad för databasberoende tester.
2. Vi ska inte ändra affärskod för att dölja databasfelet.
3. Nästa miljösteg är att starta Docker Desktop manuellt och köra om Jest.
4. Prettier-problemen ska inte massformateras innan de dokumenterats som en
   separat rigg-/kodstandardändring.
5. Legacy-testerna byggs senare som en del av moderniseringsarbetet.

## Nästa steg

1. Starta Docker Desktop.
2. Kör `docker compose up -d db`.
3. Kör `npm run db:reset`.
4. Kör `npm test` igen och spara resultatet.
5. Skapa kvalitetsskriptet `npm run verify`.
6. Implementera `/tdd` och de första hooksen.

## Uppdatering efter att Docker startades

Docker Desktop startades manuellt och den lokala PostgreSQL-containern kunde
därefter startas med `docker compose up -d db`. `npm run db:reset` återställde
både `butik` och `butik_test` utan fel.

Ny körning av `npm test`:

- 1 testsuite underkänd och 1 godkänd.
- 15 tester godkända.
- 1 test underkänt.
- Felet gäller `GET /orders/1042/price`, som svarar `404` i stället för `200`.

Orsaken är lokaliserad till plattformsberoendet i
`src/pricing/legacyPrice.ts`: implementationen startar kommandot `python3`.
På denna Windows-maskin pekar `python3` på Microsoft Store-aliaset och Python
startar därför inte från Node-processen. Samma script fungerar med projektets
installerade Python när det körs som `python src/legacy/price_calc.py 1042` och
returnerar totalen `1187.5`.

Detta är dokumenterat som ett befintligt baslinjefel. Det ska åtgärdas i ett
separat, spårbart steg och inte blandas ihop med riggens första mätning.
